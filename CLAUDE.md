## Working Principles

- Think before coding: restate the goal in one line, list assumptions, and ask if anything is unclear instead of guessing.
- Simplicity first: write the minimum code that solves the task. No speculative features, abstractions, or config options that weren't requested.
- Surgical changes: only touch code directly related to the task. Don't refactor, rename, reformat, or "improve" unrelated code. Match the existing style.
- Goal-driven: define how success will be verified (test, build, or manual check) before starting, and verify it before reporting done.
- Report honestly: if something failed, was skipped, or is uncertain, say so plainly.
